# Incident

`RightNow\Connect\v1_4\Incident` represents a customer service case/request in Oracle B2C Service Connect PHP.

This is an independent SPCX reference. Class, property, method and type names are API identifiers; the descriptions and examples here are SPCX-authored rather than copied from Oracle documentation.

Official references:

- Connect PHP: https://documentation.custhelp.com/euf/assets/devdocs/unversioned/Connect_PHP/Content/Connect%20for%20PHP%20API/RightNow%20Connect%20Object%20Model/Core/Incident.html
- REST v1.4: https://docs.oracle.com/en/cloud/saas/b2c-service/cxsvc/api-incidents.html

## Namespace

```php
use RightNow\Connect\v1_4 as RNCPHP;
```

## Source/version note

The Connect PHP property surface below is reconstructed from a public generated v1_1 class-stub set and cross-checked against Oracle's current REST v1.4 Incident schema. The current REST schema contains several fields that were not present in the older RNCPHP stub. Those fields are called out separately rather than being incorrectly labelled Connect-PHP-only or REST-only without current Connect PHP verification.

## Important nested structures

### `GroupAccount`

Used by `AssignedTo`.

- `Account` - a staff `Account` relationship.
- `StaffGroup` - staff group named-ID relationship.

When assigning to a specific account, the platform may populate the associated group. Do not blindly set contradictory account/group values.

### `Thread`

A Connect PHP Incident thread entry contains:

- `Account` - associated staff account, normally platform-populated/read-only.
- `Channel` - communication channel.
- `Contact` - associated contact where applicable.
- `CreatedTime` - read-only creation timestamp.
- `DisplayOrder` - read-only ordering value.
- `EntryType` - thread type/menu value.
- `Text` - thread body.

Legacy Connect PHP documents the thread list as append-only: code should add new entries rather than expecting to delete historical discussion entries.

### `TimeBilled`

- `Account`
- `BillableTask`
- `BillTime`
- `Comment`
- `Minutes`

The account and bill time participate in identifying the list entry in the legacy object model.

### `StatusWithType`

- `Status` - writable status named-ID.
- `StatusType` - associated type, normally read-only/platform-derived.

### `FileAttachmentIncident`

Inherits the common file fields and adds incident-specific behaviour such as `Private`.

Useful fields/methods include:

- `ContentType`
- `FileName`
- `Description`
- `Name`
- `Private`
- `URL` (read after persistence)
- `setFile()`
- `makeFile()`
- `getAdminURL()`

### `Banner`

Commonly includes the banner text plus an importance/flag value. Current REST additionally exposes banner updated-time/account information, which is another useful area to compare between bindings.

## Processing options

As an `RNObject`, Incident supports processing options such as normal processing, suppressing external events, suppressing rules, or suppressing both.

Using `SuppressRules`, `SuppressExternalEvents`, or `SuppressAll` can materially change business behaviour. Treat them as explicit integration controls, not performance shortcuts.

## Required fields and site rules

Oracle's current REST v1.4 create operation requires `primaryContact` and `subject`. Connect PHP sites can also enforce business rules, required custom fields, workspace assumptions or CPM/event logic that affects a save.

A public generic example cannot safely hard-code:

- queue IDs
- status IDs
- severity IDs
- category/product/disposition IDs
- thread entry-type IDs
- custom fields

Use metadata/configuration from the target site when available.

## Connect PHP vs REST

There are real binding differences. Examples already identified include:

- Connect PHP persists the in-process object with `save()`; REST uses POST/PATCH.
- Connect PHP can suppress rules/events using RNObject processing flags; REST has its own request/header behaviour rather than those PHP constants.
- RNCPHP uses PHP object relationships (`Contact`, `Organization`, etc.); REST commonly supplies relationship references by ID or lookup name.
- RNCPHP timestamps are historically exposed as integer timestamps; REST v1.4 returns ISO-style date/time strings.
- Legacy RNCPHP treats Incident threads as append-only, while current REST documentation says existing thread entries can be updated but cannot be removed.
- REST has a separate `incidentResponse` operation for response activity, which is not simply a one-for-one PHP method on `Incident`.

See the structured comparison in [`comparisons/incident.json`](../comparisons/incident.json).

## Custom fields

`IncidentCustomFields` is generated from the customer site's schema. This repository can document the mechanism but cannot enumerate every customer's `CustomFields->c`, custom package, menu or object relationship.
